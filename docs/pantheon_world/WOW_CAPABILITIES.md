# What PANTHEON can actually do for the world modules

*Phase 1 audit, 2026-09-07. Status is what is TRUE in this worktree today.
Every PROVEN row names the artefact or test that proves it. Nothing is
promoted because it "should work".*

## The three backends, told apart

| backend | what it is | state |
|---|---|---|
| **PANTHEON native** (`engine/pantheon_renderer`) | our own executable. Real BSP, real MD3 players, weapons, projectiles, lighting profile. No `wolfcamql.exe` process. | **WORKS.** Rebuilt from the bank on 2026-09-07 and pixel-identical to the banked binary. Software GL only. |
| **WolfcamQL** (`shot.py` via `backends.render`) | the compatibility oracle; the backend PROOF_02B was filmed on | **DOWN since 2026-09-07** — every profile exits rc=1. Cause unproven. |
| **Blender** | custom sculpting, impossible poses, Cryptomatte | **NOT PRESENT.** Blender is not installed on this machine. |

`PANTHEON_QUAKE_OFFSCREEN` is Wolfcam on a hidden desktop. It is not a native
renderer and must never be described as one.

## Implemented but NOT proven — do not lean on these

| capability | why not |
|---|---|
| `FIXED_LEGS` / `FIXED_TORSO` | proven in the evaluator, **not wired**: PANTHEON does not read `animation.cfg` for them, so both are false in every real render |
| `ANIMATION_PHASE` | closed-form, unit-tested, never differentially compared against the source |
| `POV_FAITHFUL` interpolation | five tests, all inside the module that implements it. **No independent checker.** Acceptable for an authored camera; not a foundation for demo-derived effects until closed |
| `POV_CINEMATIC` | a string constant. Nothing implements it |
| XRAY_ACTOR · depth pass · temporal blur · projectile chase | registered, never filmed |

## Not implemented

`VIEW_OFFSET` (bob, landing, step smoothing, damage kick, death roll) ·
`IMPACT_EFFECT` (explosion, trail, muzzle flash — cgame particle services the
host does not have) · sound in the native renderer · 2-D text/HUD in the
native renderer · moving brush models in the **host** (the renderer supports
them; the shot script has no keyword yet).

## What this means for the three modules

* **Temple / Hall** — buildable now. It needs staging, light and camera, and
  those are the parts that work. Its only new engine need is custom geometry.
* **Doors** — needs one host keyword and, for a real `func_door`, a compiled
  map. Both are small and named in `DOORS_V1.md`.
* **Freeze / Explain** — freeze, presenter and analysis graphic are proven;
  the *impact* is not, and the interpolation evaluator has no independent
  checker. Build it last, and label every derived quantity.
